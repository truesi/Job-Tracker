# Spring AOP

## Понятия
- **Сквозная функциональность** (cross-cutting concerns): логика, нужная во многих местах, но не входящая в бизнес-логику: транзакции, безопасность, кэширование, логирование, метрики, повторы.
- **Aspect**: модуль такой логики (класс `@Aspect`). **Join point**: точка выполнения; в Spring AOP это всегда **выполнение метода**. **Pointcut**: выражение, выбирающее join point-ы. **Advice**: код, выполняемый в них. **Weaving**: связывание аспектов с целевым кодом.
- Типы advice: `@Before`, `@AfterReturning`, `@AfterThrowing`, `@After` (как `finally`, всегда), `@Around` (оборачивает вызов; самый мощный).
- Spring AOP сплетает **в рантайме через прокси**; AspectJ сплетает при компиляции или загрузке классов, меняя байткод.

## Прокси
- **JDK dynamic proxy**: реализует интерфейсы бина. Перехватываются только методы интерфейсов, и бин нужно внедрять по интерфейсу.
- **CGLIB-прокси**: сгенерированный наследник класса бина. Spring Boot использует его по умолчанию (`spring.aop.proxy-target-class=true`).
- CGLIB не может перехватить `final` и `private` методы (и не может проксировать `final` классы). Static методы не перехватываются никогда. Такие методы молча выполняются **без** advice.
- **Self-invocation**: `this.otherMethod()` внутри бина вызывает целевой объект напрямую, мимо прокси, поэтому `@Transactional`, `@Cacheable`, `@Async` на `otherMethod` игнорируются.
- Как обойти self-invocation: вынести метод в другой бин (лучше всего); внедрить собственный прокси бина (`@Lazy` self-injection); `AopContext.currentProxy()` с `exposeProxy = true`; или сплетение AspectJ.

## Выражения pointcut
- `execution(modifiers? return-type declaring-type? name(params) throws?)`: `execution(* com.shop.service..*.*(..))` = любой метод любого класса в `service` и его подпакетах.
- `within(com.shop.web..*)`: все методы типов в этих пакетах.
- `@annotation(com.shop.Audited)`: методы с аннотацией `@Audited`. `@within(org.springframework.stereotype.Service)`: все методы классов с аннотацией `@Service`.
- `bean(*Service)` (специфично для Spring, по имени бина), `args(..)`, `this(...)` (прокси), `target(...)` (целевой объект).
- Комбинируются через `&&`, `||`, `!`, а повторно используемые выражения называются методами `@Pointcut`.

## Типы advice и @Around
- `@Around` получает `ProceedingJoinPoint`: вызови `proceed()`, чтобы выполнить метод (или не вызывай, чтобы его заблокировать), меняй аргументы, меняй или подменяй возвращаемое значение, лови и транслируй исключения, замеряй время, повторяй.
- Если забыть `return pjp.proceed()`, метод вернёт вызывающему `null` (или упадёт для примитивов).
- `JoinPoint` в других advice даёт сигнатуру, аргументы и целевой объект. `@AfterReturning(returning = "result")` и `@AfterThrowing(throwing = "ex")` привязывают результат или исключение.
- `@AfterThrowing` наблюдает исключение, но **не может его проглотить**; оно всё равно летит дальше. Для трансляции используй `@Around`.
- Порядок между аспектами: `@Order` на классе аспекта. Меньшее значение = выше приоритет = **самый внешний** (его "до" выполняется первым, а "после" последним).

## Возможности Spring на основе AOP
- `@Transactional`, `@Cacheable`/`@CacheEvict`, `@Async`, `@Retryable`, `@PreAuthorize` (безопасность методов), валидация методов через `@Validated`, метрики `@Observed`/`@Timed`.
- Репозитории Spring Data это интерфейсные прокси, чьи interceptor-ы реализуют твои методы запросов.
- Порядок interceptor-ов важен: retry должен оборачивать транзакцию (каждая попытка получает новую транзакцию); у advisor-а `@Transactional` по умолчанию самый низкий приоритет (самый внутренний).

## Spring AOP vs AspectJ
- **Spring AOP**: только выполнение методов Spring-бинов, через прокси. Просто, без особого компилятора, небольшие накладные расходы на вызов. Закрывает большинство потребностей.
- **AspectJ**: любые join point-ы (конструкторы, доступ к полям, места вызова, static и private методы), любые объекты (не только бины), нет проблемы self-invocation. Нужен компилятор `ajc` или агент load-time weaving.
- Spring использует **аннотации и язык pointcut-ов AspectJ** (`@Aspect`, `execution(...)`) даже в режиме прокси, отсюда частая путаница.

## Подводные камни
- Advice не применился: объект создан через `new` (не бин); метод private, final или static; вызов это self-invocation; pointcut не совпадает (не тот пакет или retention аннотации); аспект не является бином (`@Aspect` сам по себе не `@Component`).
- `BeanNotOfRequiredTypeException`: внедрение по конкретному классу, когда Spring создал JDK-прокси по интерфейсу.
- Тяжёлые аспекты на горячих путях (логирование каждого вызова с аргументами) стоят CPU и могут сливать в логи чувствительные данные.
