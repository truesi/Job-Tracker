# Core Java

## Объекты, равенство, строки
- `==` сравнивает ссылки для объектов и значения для примитивов. `equals()` сравнивает логическое равенство.
- **Контракт equals/hashCode**: равные объекты обязаны иметь равные hash-коды. Обратное не обязательно. Переопределяй оба метода или ни одного.
- Не используй изменяемые поля в `hashCode()` объекта, который лежит ключом в `HashMap` или элементом в `HashSet`. Поменяешь поле, и запись потеряется в чужом bucket.
- **String неизменяем**: его можно безопасно передавать между потоками, hash-код кэшируется, строка безопасна как ключ map, на этом держится string pool.
- Строковые литералы интернируются в пул. `new String("a")` всегда создаёт новый объект, а `intern()` возвращает экземпляр из пула.
- Конкатенация в цикле: используй `StringBuilder`. Одно выражение `a + b + c` компилируется в `invokedynamic` (`StringConcatFactory`, Java 9+).
- **Integer cache**: `Integer.valueOf` (а значит и autoboxing) кэширует -128..127. `Integer a = 128, b = 128; a == b` даёт `false`.
- Unboxing `null` бросает `NullPointerException`, например `int x = map.get(key);`.
- `Long.valueOf(1).equals(1)` даёт `false`: `Integer` никогда не равен `Long`.

## Методы и параметры
- Java **всегда передаёт по значению**. Для объектов копируется *ссылка*: объект можно изменить, но переприсваивание параметра не влияет на вызывающий код.
- **Overloading** разрешается на этапе компиляции по статическим типам; выигрывает самая специфичная сигнатура (`m(null)` выберет `String`, а не `Object`).
- **Overriding** разрешается в рантайме (dynamic dispatch). Статические методы *скрываются* (hiding), а не переопределяются: решает объявленный тип.
- Переопределение не может сужать видимость или бросать более широкие checked-исключения; может сузить тип возврата (covariant return).

## Классы и ООП
- Доступ: `private` < package-private < `protected` (пакет + наследники) < `public`.
- `final` класс нельзя наследовать, `final` метод нельзя переопределить, `final` переменную можно присвоить один раз, но объект по ссылке может оставаться изменяемым.
- **Абстрактный класс vs интерфейс**: у абстрактного класса есть состояние, конструкторы и одиночное наследование. У интерфейса нет состояния экземпляра, класс может реализовать много интерфейсов, есть `default`/`static` (Java 8) и `private` (Java 9) методы.
- Два интерфейса с одинаковым `default` методом: класс обязан его переопределить (можно вызвать `A.super.m()`), иначе ошибка компиляции.
- **Порядок инициализации**: static родителя → static потомка (один раз, при инициализации класса) → инициализаторы экземпляра + конструктор родителя → инициализаторы экземпляра + конструктор потомка.
- **Рецепт неизменяемого класса**: `final` класс, поля `private final`, нет сеттеров, защитные копии изменяемых входных и выходных данных, `this` не утекает из конструктора.

## Исключения
- `Throwable` → `Error` (не ловить: OOM, StackOverflow) и `Exception`. `RuntimeException` и наследники unchecked; остальные checked, их надо ловить или объявлять.
- `finally` выполняется всегда, кроме `System.exit()`, краха JVM или убитого потока. `return` внутри `finally` перекрывает return из try *и* глотает исключения: никогда так не делай.
- **try-with-resources**: работает с любым `AutoCloseable`, закрывает ресурсы в обратном порядке. Если упали и тело, и `close()`, наружу летит исключение тела, а исключение `close()` прикрепляется через `getSuppressed()`.

## Generics
- **Type erasure**: дженерик-типов нет в рантайме. Нельзя `new T()`, `instanceof List<String>`, создать `T[]`; компилятор вставляет касты и bridge-методы.
- Generics **инвариантны**: `List<String>` не является `List<Object>`. Массивы **ковариантны**: `Object[] a = new String[1]; a[0] = 1;` компилируется и бросает `ArrayStoreException`.
- **PECS** (Producer Extends, Consumer Super): читаем из `List<? extends T>`, пишем в `List<? super T>`.

## Современная Java (8 → 21)
- **Лямбды** + функциональные интерфейсы: `Function`, `Supplier`, `Consumer`, `Predicate`, `BiFunction`, ссылки на методы.
- **Streams**: ленивые, без терминальной операции ничего не выполняется, стрим одноразовый. `map` 1:1, `flatMap` 1:N. `Collectors.toMap` бросает `IllegalStateException` на дубликате ключа, если не передать merge-функцию.
- **Optional**: для возвращаемых значений, не для полей и параметров. `orElse(x)` вычисляет `x` всегда; `orElseGet(supplier)` только когда пусто.
- `var` (10), text blocks (15), records (16), pattern matching для `instanceof` (16), sealed классы (17), pattern matching для `switch` (21), virtual threads (21).
- **Records**: final класс, поля `private final`, сгенерированные конструктор/аксессоры/`equals`/`hashCode`/`toString`. Не могут наследовать класс или объявлять дополнительные поля экземпляра, но могут реализовывать интерфейсы и иметь compact-конструктор для валидации.
- **Sealed** типы: `permits` перечисляет разрешённых наследников, поэтому `switch` по ним может быть исчерпывающим без `default`.

## Разное
- `Comparable.compareTo` задаёт естественный порядок; `Comparator` задаёт внешние порядки (`Comparator.comparing(...).thenComparing(...)`).
- Сериализация: `serialVersionUID` для совместимости версий, `transient` поля пропускаются.
- `char + int` это арифметика: `'a' + 1 == 98`, но `"" + 'a' + 1` даёт `"a1"`.
