# Структуры данных и алгоритмы

## Big-O
- Типичные порядки: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!).
- Называй и **время, и память**. Различай худший, средний и **амортизированный** случай (добавление в динамический массив: O(1) амортизированно, O(n) при resize).
- Сортировку сравнениями нельзя сделать быстрее Ω(n log n). Counting и radix sort получают O(n + k), потому что не сравнивают.
- Рекурсия стоит памяти на стеке: O(глубина).

## Массивы и связные списки
- **Массив**: доступ по индексу O(1), непрерывная память, дружит с кэшем; вставка/удаление в середине O(n).
- **Связный список**: вставка/удаление O(1), если узел уже есть, поиск и доступ по индексу O(n).
- Классические задачи: развернуть список, найти цикл (медленный/быстрый указатели Флойда), найти середину (медленный/быстрый), слить два отсортированных списка, удалить n-й узел с конца (два указателя на расстоянии n).

## Стеки и очереди
- **Стек** (LIFO): проверка скобок, undo, DFS, вычисление выражений. **Монотонный стек** решает "следующий больший элемент" за O(n).
- **Очередь** (FIFO): BFS, буферизация, producer-consumer. **Дек** даёт максимум в скользящем окне за O(n).

## Хеш-таблицы
- O(1) поиск/вставка в среднем; O(n) в худшем случае, когда всё попадает в один bucket.
- Коллизии разрешаются цепочками (`HashMap` в Java) или открытой адресацией (линейное пробирование, как в dict Python и многих map в C++).
- Load factor и resize держат цепочки короткими; хорошая хеш-функция распределяет ключи равномерно.
- Типичные применения: подсчёт, дедупликация, группировка, two-sum ("видел ли я дополнение?"), кэширование.

## Деревья
- **BST**: O(log n), если сбалансировано, O(n), если выродилось (ключи вставлялись по порядку). In-order обход BST даёт отсортированные ключи.
- Обходы: pre-order, in-order, post-order (DFS), level-order (BFS через очередь).
- Сбалансированные деревья: **AVL** (строже баланс, быстрее поиск), **красно-чёрное** (меньше поворотов, используется в `TreeMap`). **B-tree / B+tree**: широкие узлы с сотнями ключей, мало уровней, структура индексов БД.
- **Куча**: полное бинарное дерево в массиве; минимум или максимум в корне. Вставка/извлечение O(log n), просмотр O(1), heapify O(n). Очереди с приоритетом, top-K, Дейкстра.
- **Trie**: префиксное дерево; поиск O(длина ключа). Автодополнение, поиск по префиксу.

## Графы
- Представление: списки смежности (разреженные графы, память O(V + E)) или матрица смежности (плотные графы, O(V²)).
- **BFS**: кратчайший путь в невзвешенном графе, O(V + E). **DFS**: поиск циклов, компоненты связности, топологическая сортировка.
- **Дейкстра**: кратчайшие пути с неотрицательными весами, O((V + E) log V) с кучей. **Беллман-Форд**: допускает отрицательные веса, O(V·E).
- **Топологическая сортировка** (алгоритм Кана): упорядочить задачи с зависимостями в DAG.
- **Union-Find** (система непересекающихся множеств): запросы связности, минимальное остовное дерево Краскала; почти O(1) на операцию.

## Алгоритмические приёмы
- **Два указателя** (отсортированные массивы, пары), **скользящее окно** (подмассивы и подстроки), **бинарный поиск** (в том числе "бинарный поиск по ответу").
- **Рекурсия + мемоизация** и **динамическое программирование**: перекрывающиеся подзадачи + оптимальная подструктура. **Жадный алгоритм**: локальный выбор, безопасность которого доказана. **Перебор с возвратом** (backtracking): попробовать, рекурсивно спуститься, откатить.
- Сортировки: quicksort O(n log n) в среднем, O(n²) в худшем, на месте, нестабильная. Merge sort O(n log n) гарантированно, стабильная, O(n) доп. памяти. Heapsort O(n log n), на месте, нестабильная.
- Бинарному поиску нужен отсортированный вход; считай `mid = lo + (hi - lo) / 2`, чтобы не переполнить int.
- Структуры из мира system design: **фильтр Блума** (возможны ложноположительные ответы, ложноотрицательных нет), **LRU-кэш** (хеш-таблица + двусвязный список), **skip list**, **консистентное хеширование**.
